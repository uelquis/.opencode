## Conventions
  
- Bare paths (e.g. `references/guide.md`) resolve from the skill root.
- `{skill-root}` resolves to this skill's installed directory (where `SKILL.md` lives).
- `{project-root}` resolves to the root of the project you are working on (where `AGENTS.md` lives).
- Reports generated by this skill are stored in `{project-root}/review` by default. The naming convention for the reports is `review-<date>-<title>.md`, where `<date>` is the current date, and `title` is a brief description of the code being reviewed.

## On Code Review

When reviewing code, follow these requirements:

Before reviewing code, make sure to check the project's specifications and requirements to ensure that the code meets the expected functionality, performance criteria, coding conventions, the specified architecture, and any other relevant guidelines. Be concise and clear in your feedback, avoiding unnecessary technical jargon or complex explanations. Use examples and/or references to relevant documentation or best practices to support your recommendations. 

## Code Review Report Guidelines

Follow these guidelines to write a code review report:

Don't forget to include the date, the reviewer's name, the scope of the review, and any relevant references or links to documentation in the report. When classifying issues, use the following categories:
- **Critical**: Issues that must be addressed immediately, as they may cause system failures, security vulnerabilities, or significant performance degradation.
- **Major**: Issues that should be addressed promptly, as they may lead to functional problems, maintainability challenges, or potential security risks.
- **Minor**: Issues that are less urgent but should be addressed to improve code quality, maintainability, or adherence to best practices. These issues may include code style inconsistencies, minor performance optimizations, or documentation improvements.
- **Nipticks**: Very small issues that are not critical but can be improved for better code quality, readability, or maintainability. These may include minor formatting inconsistencies, variable naming improvements, or small refactoring suggestions.

You are required to provide an answer to the following questions for each issue found:
1. Where is the issue located? (Provide the file name and if possible, the line number)
2. What is the issue? (Provide a clear and concise description of the problem)
3. Why is it an issue? (Explain the impact of the issue on the code quality, maintainability, or adherence to best practices)
4. How can it be fixed? (Provide actionable suggestions for improvement, including code examples or references to relevant documentation or best practices)

You are required to write the code review report.
